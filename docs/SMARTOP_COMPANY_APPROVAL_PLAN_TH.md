# เอกสารเสนออนุมัติโครงการ SmartOP

23 พฤศจิกายน 2569 · ฉบับ 1.0 · เสนอเพื่อพิจารณาอนุมัติ

ฉบับภาษาไทย ครอบคลุมเนื้อหา แผนภาพ ตารางงาน และภาคผนวกทุกส่วน โดยคงชื่อผลิตภัณฑ์เทคโนโลยี รหัสเอกสาร รหัสงาน และแหล่งอ้างอิงเพื่อใช้ตรวจสอบกับต้นฉบับ

เสนอเพื่ออนุมัติขอบเขตโครงการ โครงสร้างระบบ วิธีดำเนินงาน และเกณฑ์ตรวจรับก่อนขึ้นใช้งานจริง

| --- | --- |
| รหัสเอกสาร | SMARTOP PROPOSAL 2026 001 |
| ฉบับและวันที่ | ฉบับ 1.0  /  23 พฤศจิกายน 2569 |
| ผู้รับเอกสาร | ผู้บริหารและผู้รับผิดชอบงานของบริษัทผู้ว่าจ้าง |
| ผู้จัดทำ | ทีมโครงการ SmartOP |

### เรื่องที่ขออนุมัติ

ขออนุมัติพัฒนาระบบที่เชื่อมงานพนักงานและไซต์ คลังวัสดุ จัดซื้อจัดจ้าง คำสั่งซื้อ วางบิล การรับจ่าย บัญชี และภาษี โดยต่อยอดระบบเดิม และเปิดทุกโมดูลพร้อมกันเมื่อผ่านการทดสอบและการรับรองยอดของบริษัท

เอกสารครอบคลุมบริษัทเดียวที่มีหลายไซต์หรือสาขา ใช้เว็บและ Excel เป็นข้อมูลตั้งต้น และให้เจ้าของข้อมูลอนุมัติส่วนต่างก่อนย้ายข้อมูล แผนส่งมอบมี 44 งานหลักและผูกกับ 48 ประเด็นตรวจติดตามจากการตรวจระบบและไฟล์บริษัท

### ขอบเขตการอนุมัติฉบับนี้

การลงนามใช้รับรองแนวทาง ขอบเขต และเกณฑ์ดำเนินโครงการ วงเงิน ระยะเวลาดำเนินงาน และวันเปิดใช้งานมีผลเมื่อผู้ว่าจ้างอนุมัติแผนฐานและข้อเสนอค่าใช้จ่ายภายหลังการประเมินข้อมูลและทรัพยากร ไม่ใช้เอกสารนี้แทนการอนุมัติยื่นภาษีหรือปล่อยจ่ายเงินรายรายการ

ฐานอ้างอิงการตรวจ 22 พฤศจิกายน 2569  |  เอกสารจัดทำ 23 พฤศจิกายน 2569

ฐานอ้างอิง 5dd38b5 และเอกสารออกแบบใน คลังซอร์สโค้ด วันที่ 22 พฤศจิกายน 2569


## สารบัญและวิธีใช้เอกสาร

ส่วนต้นใช้ประกอบการตัดสินใจและกำกับโครงการ ภาคผนวก ก ระบุงานส่งมอบครบ 44 งาน ภาคผนวก ข แสดงประเด็นตรวจติดตาม 48 ข้อพร้อมงานอ้างอิง และส่วนท้ายเป็นแหล่งข้อมูลกับแบบลงนามอนุมัติ


## 1 บทสรุปและข้อตกลงโครงการ

SmartOP จะเป็นระบบทำงานหลักร่วมกันของบริษัทตั้งแต่เอกสารต้นทางถึงบัญชีและภาษี ลดการคีย์ซ้ำ และให้ทุกยอดตรวจย้อนกลับถึงเอกสาร ผู้อนุมัติ และเวอร์ชันกฎที่ใช้ได้ การรับรองความพร้อมวัดจาก กระบวนการทำงาน และยอดที่กระทบตรงกัน ไม่วัดจากจำนวนหน้าจอหรือตาราง

| ประเด็น | ข้อกำหนดที่ยืนยันแล้ว |
| --- | --- |
| ขอบเขตองค์กร | เริ่มบริษัทเดียว หลายไซต์หรือสาขา โครงสร้างข้อมูลเตรียมรองรับหลายบริษัท แต่รุ่นแรกตรวจรับนิติบุคคลเดียว |
| วิธีเปิดระบบ | พัฒนาและตรวจรับเป็นชุดบน ระบบทดสอบก่อนใช้งานจริง แล้วเปิดทุกโมดูลพร้อมกันหลัง การทดสอบและตรวจรับโดยผู้ใช้งาน ทั้งบริษัท |
| ข้อมูลปัจจุบัน | ใช้ทั้งเว็บและ Excel ส่วนต่างต้องให้เจ้าของข้อมูลอนุมัติรายโมดูลก่อน นำเข้าข้อมูล |
| ทะเบียนภาษี | ตั้งค่าจด ภาษีมูลค่าเพิ่ม หรือไม่จด ภาษีมูลค่าเพิ่ม ตามทะเบียนและวันที่มีผล พร้อมหลักฐานและประวัติ |
| การนำส่งภาษี | รองรับไฟล์และ ช่องทางเชื่อมต่อระบบ ตามสิทธิ์ แบบ และช่องทางที่ผ่านการอนุมัติและทดสอบ |
| การจ่ายเงินรุ่นแรก | อนุมัติในระบบ ส่งไฟล์ผ่านธนาคาร และนำผลจริงกับ รายการเดินบัญชี กลับมากระทบยอด |

### ผลที่บริษัทควรได้รับ

- ข้อมูลพนักงาน สัญญา ไซต์ และกำลังคน เชื่อมค่าจ้าง ต้นทุน และการเรียกเก็บตามหลักฐานที่อนุมัติ
- ใบขอซื้อ และ ใบสั่งซื้อ เชื่อมตรวจรับ คลัง เจ้าหนี้ และการจ่าย โดยไม่บันทึกสต็อกหรือค่าใช้จ่ายซ้ำ
- ลูกหนี้ เจ้าหนี้ เงินสด ธนาคาร บัญชี และทะเบียนภาษีตรวจสอบยอดร่วมกันได้
- มีผู้รับผิดชอบ สายอนุมัติ หลักฐาน และรายงานข้อผิดปกติสำหรับทุกธุรกรรมสำคัญ

## 2 สถานะปัจจุบันและเรื่องที่ต้องแก้ก่อนใช้งานจริง

ตรวจฐานโค้ด 5dd38b5 พบแบบจำลองข้อมูล 102 รายการ และไฟล์เส้นทางเชื่อมต่อ 63 ไฟล์ พัฒนาฐานข้อมูลและบริการรับจ่ายคลังภายในระยะ P3 แล้ว ส่วนบัญชีคู่และภาษีครบวงจรยังอยู่ในขั้นออกแบบ ผลทดสอบต่อไปนี้เป็นหลักฐานจากรอบพัฒนาก่อนหน้า ยังไม่ใช่การรับรองใช้งานจริง

| ส่วนที่ตรวจ | สถานะและผลต่อแผน |
| --- | --- |
| คลัง P3 | มี บริการประมวลผล รับ จ่าย โอน คืน ปรับนับและต้นทุนเฉลี่ย ต้องต่อ กระบวนการทำงาน อนุมัติ ช่องทางเชื่อมต่อระบบ และหน้าจอ |
| ผลตรวจทางเทคนิคเดิม | การทดสอบ ทั่วไป 134 และ การทดสอบฐานข้อมูล 38 ผ่าน พร้อม การตรวจชนิดข้อมูล การตรวจเส้นทางระบบ 115 เส้นทาง และ การสร้างชุดโปรแกรมสำหรับใช้งานจริง บนฐานทดสอบ |
| ไฟล์บริษัท | ตรวจโครงสร้างครบ 50 ชีต ไฟล์พนักงานมี การอ้างอิงไฟล์ภายนอก และ ข้อมูลราคาหลัก มี 12 รายการราคาไม่มี รหัส ที่ต้องทบทวน |
| ระบบเงินเดือน | มี การทำงานล่วงเวลา 20 ชั่วโมงและภาษี 1% แบบตายตัว และ การค้นข้อมูลลงเวลา ไม่จำกัดวันที่ตาม งวด ต้องแก้ก่อนใช้จ่ายหรือยื่นจริง |
| บัญชีและภาษี | ยังไม่มี สมุดรายวัน และ บัญชีแยกประเภท หรือ กลไกจัดทำและนำส่งแบบภาษี ใน โครงสร้างฐานข้อมูล ปัจจุบัน ต้องสร้างและทดสอบ การเชื่อมข้อมูลต้นทาง |
| ฐานข้อมูลเดิม | ผลตรวจล่าสุดบันทึก ความคลาดเคลื่อนของโครงสร้างฐานข้อมูล และไม่มี ประวัติการปรับโครงสร้างฐานข้อมูล ต้องตรวจยืนยันบนสำเนาที่ได้รับอนุญาตก่อน ปรับโครงสร้างฐานข้อมูล |
| การสำรองข้อมูล และ การกู้คืนเมื่อเกิดภัยพิบัติ | มี การสำรองข้อมูล สคริปต์ แต่หน้าจอแสดงข้อมูล ตรวจยืนยันแล้ว แบบจำลอง ยังต้องมี หลักฐานการกู้คืนข้อมูล จริง |

### เงื่อนไขก่อนเริ่มข้อมูลจริง

บริษัทต้องรับรองแหล่งข้อมูลหลัก กฎ ระบบเงินเดือน และ การวางบิล รายไซต์ ทะเบียนภาษี ผังบัญชี และสายอนุมัติ ทีมเทคนิคต้องสำรองและทดสอบคืนข้อมูล พร้อมจัด สภาพแวดล้อมระบบ ทดสอบที่แยกจากงานจริง ก่อนเปิดคำสั่งที่เปลี่ยนเงิน สต็อก หรือแบบภาษี


## 3 ขอบเขตระบบที่เสนออนุมัติ

| ระบบ | ผลส่งมอบหลัก |
| --- | --- |
| ข้อมูลพื้นฐาน | บริษัท สาขา ลูกค้า ผู้ขาย พนักงาน ไซต์ โครงการ วัสดุ หน่วยนับ ผังบัญชี กฎภาษีและเลขเอกสาร |
| พนักงานและกำลังคน | ประวัติ การมอบหมายไซต์ กะ ลงเวลา การทำงานล่วงเวลา ลา แก้เวลา ส่งตัว เข้าและพ้นสภาพ |
| ระบบเงินเดือน และพอร์ทัล | คำนวณจาก งวด จริง ตรวจและอนุมัติ เผยแพร่ สลิปเงินเดือน ภาษีเงินเดือน ประกันสังคม และไฟล์จ่าย |
| ขายและสัญญาลูกค้า | เสนอราคา คำสั่งซื้อ สัญญา ตารางราคา หลักฐานบริการ และการคำนวณเรียกเก็บ |
| จัดซื้อจัดจ้าง | ใบขอซื้อ ใบขอเสนอราคา เปรียบเทียบราคา ใบสั่งซื้อ สัญญาจ้าง งวดงาน หลักประกันและ ฉบับแก้ไข |
| ตรวจรับ | รับสินค้ารอตรวจ ตรวจคุณภาพ รับบางส่วน ปฏิเสธ ใบรับสินค้า และใบตรวจรับงานบริการ |
| คลังวัสดุ | รหัสวัสดุ และ รุ่นย่อยของวัสดุ ยอดตาม ตำแหน่งเก็บ จองของ เบิกจ่าย โอน คืน ตรวจนับ และต้นทุนไซต์ |
| วางบิลและเจ้าหนี้ลูกหนี้ | วางบิลลูกค้า รับวางบิลผู้ขาย ใบแจ้งหนี้ ใบลดหนี้และใบเพิ่มหนี้ รับและจ่ายบางส่วนหลายใบ |
| การเงินและธนาคาร | เสนอจ่าย อนุมัติ ไฟล์ธนาคาร กระทบยอด เงินทดรอง ค่าใช้จ่าย เงินสดย่อยและ ประมาณการกระแสเงินสด |
| บัญชี | ผังบัญชี งวด สมุดรายวัน และ บัญชีแยกประเภท รายการกลับบัญชี ปิดงวด งบทดลอง งบการเงินและ การลงบัญชีจากเอกสารต้นทาง |
| ภาษีและนำส่ง | ภาษีมูลค่าเพิ่ม ภาษีหัก ณ ที่จ่าย หนังสือรับรอง แบบภาษี การยื่น ชำระ หลักฐาน ยื่นเพิ่มเติม และภาษีอื่นตาม หน้าที่ตามกฎหมาย |
| ระบบพ่วงและแพลตฟอร์ม | สินทรัพย์ ค่าเสื่อม คุณภาพ อาชีวอนามัย ความปลอดภัยและสิ่งแวดล้อม การอบรม บำรุงรักษา ข้อตกลงระดับบริการ รายการติดตามงาน รายงาน ตัวประมวลผลงานเบื้องหลัง เอกสาร สิทธิ์ การสำรองข้อมูล และ การติดตามสถานะระบบ |

ทุกหมวดใน ขอบเขตที่ต้องพร้อมก่อนเปิดระบบ ต้องผ่านการตรวจรับก่อนเปิดพร้อมกัน รายการที่ขึ้นกับข้อเท็จจริง เช่น ภาษีต่างประเทศ อากรตามตราสาร หรือเอกสารแรงงานเฉพาะประเภท ระบุ อยู่ในเงื่อนไข หรือ ไม่อยู่ในเงื่อนไข พร้อมเหตุผลและผู้อนุมัติ ห้ามใช้ ไม่อยู่ในเงื่อนไข ปิดงานหลักที่ยังไม่เสร็จ


## 4 กระบวนการเชื่อมงานทั้งบริษัท

แผนภาพสองวงจรหลัก วงจรจัดซื้อถึงชำระเงิน และ วงจรขายถึงรับเงิน เชื่อมบัญชีและภาษีจาก ข้อมูลต้นทาง ที่อนุมัติ

ฝั่งซื้อเริ่มจากความต้องการและ ใบขอซื้อ ไป ใบขอเสนอราคา และ ใบสั่งซื้อ จากนั้นสินค้าผ่านใบตรวจรับก่อนเข้าคลัง ส่วนงานจ้างผ่านใบตรวจรับงานบริการ เจ้าหนี้และการจ่ายอ้างเอกสารที่ตรวจครบและไม่ลงต้นทุนซ้ำ

ฝั่งขายเริ่มจากสัญญาและคำสั่งซื้อ เชื่อมแผนกำลังคน หลักฐานปฏิบัติงาน การเรียกเก็บ วางบิล และรับเงิน แยก การทำงานล่วงเวลา ที่จ่ายพนักงานออกจาก การทำงานล่วงเวลา ที่เรียกเก็บลูกค้า และเก็บหลักฐานส่วนลดหรือหักค่าบริการ


## 5 ระบบภาษีและหลักฐานการนำส่ง

ข้อมูลภาษีผูกกับนิติบุคคลและสาขาตามทะเบียน มีวันที่มีผลและประวัติ เอกสารแต่ละฉบับเก็บ สำเนาข้อมูล ณ เวลาออกเอกสาร ของคู่ค้า ภาษี และกฎที่ใช้ การแก้ค่าพื้นฐานจึงไม่เปลี่ยนเอกสารที่ออกแล้ว

| ภาษีมูลค่าเพิ่ม | ภาษีซื้อและขาย แยกอัตราปกติ ศูนย์ ยกเว้นและนอกขอบเขต รวมสิทธิ์ภาษีซื้อและ ภ.พ.30 ตาม ข้อมูลทะเบียน |
| ภาษีหัก ณ ที่จ่าย | ภาษีที่บริษัทหักและที่ลูกค้าหัก ภ.ง.ด.1 3 53 และ 50 ทวิ ตามประเภทเงินได้ คู่ค้าและการจ่ายจริง |
| ภาษีตามเงื่อนไข | ภ.พ.36 ภ.ง.ด.54 ภาษีเงินได้นิติบุคคล ภ.ง.ด.50 และ 51 อากรแสตมป์ และแบบอื่นเมื่อบริษัทเข้าเงื่อนไข |
| การจัดทำแบบ | ดึง ข้อมูลต้นทาง ที่อนุมัติ ตรวจทะเบียน กระทบยอด ตรวจทาน อนุมัติ และตรึงเวอร์ชันพร้อม ค่าตรวจสอบความถูกต้อง |
| ช่องทางนำส่ง | ไฟล์ตาม รูปแบบ ที่ผ่านเครื่องมือทางการ และ ช่องทางเชื่อมต่อระบบ เฉพาะแบบและสิทธิ์ที่ได้รับอนุมัติ พร้อม ช่องทางยื่นโดยผู้ใช้ดำเนินการ |
| ผลยื่นและการชำระ | แยกส่งแล้ว กำลังประมวลผล รับแบบแล้ว และชำระยืนยัน ใช้ผลทางการกับหลักฐานธนาคาร |
| ยื่นเพิ่มเติม | สร้างเวอร์ชันอ้างต้นฉบับ แสดงส่วนต่างและเหตุผล เก็บหลักฐาน ไม่แก้แบบเดิมทับ |

### ข้อกำหนดที่ต้องยืนยันก่อนเปิดใช้

ฝ่ายบัญชีและผู้รับผิดชอบภาษีอนุมัติทะเบียน หน้าที่ตามกฎหมาย จุดเกิดภาษี อัตรา ฐาน การปัดเศษ วันที่ครบกำหนด และกฎเฉพาะบริษัทจากแหล่งทางการ กฎที่ยังไม่ยืนยันคงสถานะรอตรวจและไม่ถูกใช้คำนวณจริง

ประกันสังคมและการส่งงบ กรมพัฒนาธุรกิจการค้า ใช้ทะเบียน ช่องทาง และหลักฐานแยกจากสรรพากร การสร้างไฟล์หรือได้รับ สถานะตอบกลับของช่องทางเชื่อมต่อ สำเร็จ เพียงอย่างเดียวไม่ใช้รับรองว่ายื่นหรือชำระสำเร็จ


## 6 โครงสร้างระบบและฐานข้อมูลเป้าหมาย

ต่อยอดเทคโนโลยีเดิม ได้แก่ Next.js TypeScript Prisma และฐานข้อมูลตระกูล MySQL โดยใช้โปรแกรมหลักเดียวที่แยกส่วนงานชัดเจน แยกหน้าจอและช่องทางเชื่อมต่อออกจากกฎธุรกิจ ใช้กลไกตรวจสิทธิ์ อนุมัติ เลขเอกสาร บันทึกตรวจสอบ พื้นที่เอกสารจำกัดสิทธิ์ และคิวส่งงานคงทนร่วมกัน

| ชั้นระบบ | หน้าที่และข้อมูลที่รับผิดชอบ |
| --- | --- |
| หน้าจอและ ช่องทางเชื่อมต่อระบบ | รับข้อมูลที่ตรวจรูปแบบแล้ว ตรวจ วาระการเข้าสู่ระบบ และขอบเขตอำนาจ ทุกคำสั่ง แสดง กำลังโหลด ไม่พบข้อมูล ข้อผิดพลาด และผลสำเร็จตามหลักฐาน |
| บริการประมวลผลธุรกิจ | ควบคุม กรณีใช้งาน และ การเปลี่ยนสถานะตามขั้นตอน ตรวจผู้อนุมัติ การป้องกันคำสั่งซ้ำ และเวอร์ชันข้อมูล |
| ข้อมูลพื้นฐาน | บริษัท และ สาขา คู่ค้า พนักงาน ไซต์ วัสดุ หน่วยนับ ราคา บัญชีและ ประวัติรุ่นข้อมูลภาษี |
| เอกสารธุรกิจ | ใบขอซื้อ ใบเสนอราคา ใบสั่งซื้อ สัญญา การตรวจรับ การรับรองผลงาน ใบเบิก ใบแจ้งหนี้ การวางบิล และ การจัดสรรยอด |
| บัญชีรายการเคลื่อนไหว และการกระทบยอด | รายการเคลื่อนไหวคลัง สมุดรายวัน บัญชีแยกประเภท บัญชีภาษี และ การลงบัญชีจากเอกสารต้นทาง พร้อมข้อมูลอ้างอิงและ รายการกลับบัญชี |
| งานภายนอก | ตัวประมวลผลงานเบื้องหลังส่งและติดตามผลธนาคาร ภาษี อีเมล เอกสาร และ นำเข้าข้อมูล ด้วย รหัสอ้างอิง ที่ป้องกันรายการซ้ำ |
| ปฏิบัติการ | การติดตามสถานะระบบ บันทึกตรวจสอบย้อนหลัง พื้นที่จัดเก็บ การสำรองข้อมูล กู้คืนข้อมูล และการควบคุม ระบบพัฒนา ระบบทดสอบ ระบบทดสอบก่อนใช้งานจริง ระบบใช้งานจริง |

### กฎข้อมูลที่บังคับใช้ร่วมกัน

- ยอดเงินใช้ เลขทศนิยมฐานสิบแบบแม่นยำ และ สกุลเงิน ชัดเจน ไม่ใช้ เลขทศนิยมแบบประมาณค่า คำนวณเงิน และกำหนด ความละเอียดทศนิยม การปัดเศษตามนโยบาย
- ทุก บัญชีรายการเคลื่อนไหว อ้าง ข้อมูลต้นทาง และ บริษัท สอดคล้องกัน รายการที่ลงบัญชีแล้ว แก้ด้วย รายการกลับบัญชี หรือ รายการปรับปรุง ที่อนุมัติ
- เลขเอกสารออกด้วย ธุรกรรมที่สำเร็จหรือยกเลิกทั้งชุด และ ข้อบังคับไม่ให้ข้อมูลซ้ำ ไม่ใช้ การนับจำนวนรายการ บวกหนึ่ง
- คง ข้อมูลลูกค้า ข้อมูลผู้ขาย และ ใบรับสินค้า ของเดิม ใช้ การเพิ่มโครงสร้างโดยรักษาข้อมูลเดิม และตรวจ การจับคู่ข้อมูล ก่อนถอน ระบบเดิม
- ขยายจาก 102 แบบจำลองข้อมูล ตามแบบข้อมูลเป้าหมายทีละชุด ไม่ถือว่าตารางที่มีแล้วคือ กระบวนการทำงาน ที่เสร็จแล้ว

## 7 แผนย้ายข้อมูลจากเว็บและ Excel

ใช้ แหล่งข้อมูลหลักที่รับรอง ที่เจ้าของข้อมูลอนุมัติรายโมดูล หากเว็บและ Excel ต่างกัน ให้ระบบสร้างรายงานส่วนต่างและรอ คำตัดสิน ที่บันทึกผู้อนุมัติ ไม่เลือกข้อมูลใหม่กว่าหรือเขียนทับอัตโนมัติ

| ขั้น | การดำเนินการและหลักฐาน |
| --- | --- |
| 1 สำรวจ | ระบุ สภาพแวดล้อมระบบ สคีมาจริง ประวัติการปรับโครงสร้างฐานข้อมูล ช่วงข้อมูล คู่มือและเจ้าของข้อมูล พร้อมรายการ ข้อมูลอ่อนไหว |
| 2 สำรองและคืน | สำรอง ฐานข้อมูล และเอกสาร คืนบน สำเนาระบบที่ได้รับอนุญาต และยืนยันข้อมูล กลไกทำงานอัตโนมัติในฐานข้อมูล และ ค่าตรวจสอบความถูกต้อง |
| 3 วิเคราะห์ | อ่านแยกข้อมูล และ จับคู่ข้อมูล ชื่อ/รหัส/สาขา วันที่และ หน่วยนับ ตรวจ การอ้างอิงไฟล์ภายนอก รายการซ้ำ ข้อมูลที่ไม่มีรายการแม่อ้างอิง และ รหัสวัสดุ รุ่นย่อยของวัสดุ |
| 4 ตรวจส่วนต่าง | เทียบเว็บกับ Excel ตาม รหัสอ้างอิงทางธุรกิจ เก็บ ข้อมูลขัดแย้ง และ คำตัดสิน ของเจ้าของข้อมูลรายโมดูล |
| 5 ทดลองย้าย | ตรวจสอบความถูกต้อง แสดงตัวอย่าง รายงานข้อผิดพลาด และ การทดลองโดยยังไม่เปลี่ยนข้อมูลจริง บน ระบบทดสอบก่อนใช้งานจริง แก้ ข้อผิดพลาดระดับวิกฤต ก่อนอนุมัติ |
| 6 ยืนยันและนำเข้า | ตรึงข้อมูล ค่าตรวจสอบความถูกต้องของไฟล์ และ รุ่นกฎการจับคู่ข้อมูล นำเข้าใน ธุรกรรมที่สำเร็จหรือยกเลิกทั้งชุด แบบ ทำซ้ำเมื่อเกิดข้อขัดข้อง ไม่ซ้ำ เก็บ ร่องรอยอ้างอิงแถวข้อมูลต้นทาง และ บันทึกตรวจสอบย้อนหลัง |
| 7 กระทบยอด | ตรวจ พนักงาน/การมอบหมายงาน, จำนวนและมูลค่าสินค้าคงคลัง, ลูกหนี้การค้า เจ้าหนี้การค้า บัญชีแยกประเภท ภาษี ระบบเงินเดือน และเอกสารที่เปิดค้าง ให้เจ้าของข้อมูลลงนาม |
| 8 ตัดเข้าสู่ระบบใหม่ | หยุดแก้ข้อมูลตามเวลาที่อนุมัติ เก็บ ข้อมูลส่วนต่างครั้งสุดท้าย ย้ายครั้งสุดท้าย ตรวจยอดและเปิดทุกโมดูลพร้อมกัน |

ยอดเบิกวัสดุย้อนหลังไม่ใช้แทน ยอดยกมาสินค้าคงคลัง ต้องมี จำนวน และ การตีมูลค่า ที่ตรวจนับหรือรับรองแล้ว เอกสารที่ยังไม่จบ เช่น ใบสั่งซื้อ ค้างรับ ลูกหนี้ค้าง เจ้าหนี้ค้าง เงินทดรอง และเครดิตภาษี ต้องมีบัญชีเปิดค้างและ รหัสอ้างอิงข้อมูลต้นทาง แยก

ใช้ชุดคำสั่งปรับโครงสร้างฐานข้อมูลที่ตรวจแล้ว ห้ามผลักโครงสร้าง ล้างฐานข้อมูล ลบตาราง หรือบันทึกว่าปรับโครงสร้างสำเร็จทั้งชุดโดยไม่พิสูจน์ผล ต้องซ้อมบนสำเนาก่อนใช้กับฐานจริง


## 8 แผนพัฒนาและหมุดหมายการส่งมอบ

พัฒนาและทดสอบเป็นชุดภายใน ระบบพัฒนา และ ระบบทดสอบก่อนใช้งานจริง เพื่อควบคุม งานที่ต้องพร้อมก่อน แต่การเปิดให้ลูกค้าจริงเป็นครั้งเดียวหลังผ่าน การทดสอบและตรวจรับโดยผู้ใช้งาน ครบ ขอบเขตที่ต้องพร้อมก่อนเปิดระบบ ชุดงาน A0 ถึง A7 เชื่อม ระยะ P0 ถึง P8 ของแผนเดิมและรายละเอียด 44 งานในภาคผนวก ก

| ชุดงาน | สิ่งส่งมอบและเงื่อนไขผ่าน |
| --- | --- |
| A0 ความพร้อม | ฐานอ้างอิงที่รับรอง สำเนาระบบ กู้คืนข้อมูล การจัดการตัวตนและสิทธิ์ และ ระบบเงินเดือน ที่ใช้ข้อมูลจริงผ่านก่อนนำยอดเข้าบัญชีหรือแบบภาษี |
| A1 พื้นฐานและ บัญชีแยกประเภท | บริษัท สาขา ภาษีมูลค่าเพิ่ม คู่ค้า การอนุมัติ เลขเอกสาร ผังบัญชี งวด และ สมุดรายวันที่เดบิตเท่ากับเครดิต |
| A2 คลัง | ต่อ บริการประมวลผล P3 เป็น กระบวนการทำงาน ช่องทางเชื่อมต่อระบบ และ หน้าจอผู้ใช้งาน ครบ การจองวัสดุ ตรวจรับ ยืนยันรับและกระทบยอด |
| A3 ซื้อและจ้าง | ใบขอซื้อ ใบขอเสนอราคา และใบสั่งซื้อ สัญญาจ้าง การตรวจคุณภาพ การรับรองผลงาน ใบแจ้งหนี้ ตรวจจับคู่ วางบิลผู้ขายและเจ้าหนี้ |
| A4 ขายและการเงิน | คำสั่งซื้อของลูกค้า การวางบิล ใบแจ้งหนี้ ลูกหนี้การค้า การจ่ายเงิน ไฟล์รับจ่ายธนาคาร และ การกระทบยอดรายการเดินบัญชี |
| A5 ภาษี | กฎภาษี ทะเบียน หนังสือรับรอง แบบภาษีที่อนุมัติ ช่องทาง หลักฐาน การจ่ายเงิน และแก้ไขเพิ่มเติม |
| A6 ระบบบริษัท | กำลังคน ระบบเงินเดือน ประกันสังคม สินทรัพย์ ค่าใช้จ่าย ข้อตกลงระดับบริการ บำรุงรักษา รายงานและข้อมูลส่วนบุคคลตามขอบเขตงาน |
| A7 เปิดใช้งาน | การเชื่อมระบบ เว็บเบราว์เซอร์ ความปลอดภัย กู้คืนข้อมูล การทดสอบและตรวจรับโดยผู้ใช้งาน การอบรม ขั้นสุดท้าย การปรับโครงสร้างหรือย้ายข้อมูล และลงนาม เปิดใช้งานจริง |

### การจัดทำกำหนดการและควบคุมงบ

หลังสำรวจ A0 และยืนยัน กฎข้อมูลหลัก ใน A1 ให้ทีมแตก 44 งานเป็น งานพัฒนาย่อย ประเมิน ปริมาณงานและทรัพยากร งานที่ต้องพร้อมก่อน และจำนวนคน แล้วเสนอ กำหนดการฐานที่อนุมัติ พร้อมต้นทุนพัฒนา ย้ายข้อมูล ทดสอบ อบรม และดูแลระบบให้ผู้ว่าจ้างอนุมัติ รวมค่าใช้จ่ายประจำด้าน บริการเครื่องแม่ข่าย พื้นที่จัดเก็บ การสำรองข้อมูล ผู้ให้บริการภายนอก หนังสือรับรอง และ บำรุงรักษา

ยังไม่มีข้อมูลยืนยันขนาดทีม อัตราค่าบริการ และวงเงิน จึงไม่กำหนดราคาหรือวันเปิดระบบเป็นข้อผูกพันในฉบับนี้ การเปลี่ยนขอบเขตงาน กฎ ข้อมูล หรือช่องทาง ผู้ให้บริการภายนอก หลังอนุมัติ ต้องมี การประเมินผลกระทบ และ คำขอเปลี่ยนแปลง ก่อนปรับแผนฐาน


## 9 ผู้รับผิดชอบ สิทธิ์และการกำกับงาน

| งานกำกับ | ผู้ดำเนินการ | ผู้อนุมัติ |
| --- | --- | --- |
| ขอบเขตและแผนฐาน | หัวหน้าโครงการร่วมกับเจ้าของกระบวนการ | ผู้บริหารหรือผู้สนับสนุนโครงการ |
| ข้อมูลบริษัทและภาษี | ฝ่ายบัญชีและผู้รับผิดชอบภาษี | ผู้มีอำนาจของบริษัท |
| ระบบเงินเดือน และกำลังคน | ฝ่ายบุคคล และ ฝ่ายปฏิบัติการ | ผู้รับผิดชอบ ฝ่ายบุคคล และการเงินตามอำนาจ |
| จัดซื้อ ตรวจรับ คลัง | ฝ่ายจัดซื้อ ผู้ตรวจรับและ ฝ่ายคลัง | ผู้มีอำนาจตามวงเงินและขอบเขตอำนาจ |
| รับจ่ายและธนาคาร | ลูกหนี้การค้า เจ้าหนี้การค้า ฝ่ายบริหารเงิน | ผู้อนุมัติและผู้ปล่อยจ่ายที่แยกหน้าที่ |
| บัญชีและปิดงวด | ผู้จัดทำบัญชีและผู้ตรวจทาน | ผู้รับผิดชอบบัญชีตามอำนาจ |
| ทดสอบและย้ายข้อมูล | ทีมเทคนิค ทีมตรวจคุณภาพ ทีมดูแลระบบ และเจ้าของข้อมูล | เจ้าของกระบวนการและหัวหน้าโครงการ |
| เปิดระบบจริง | ทีมโครงการและ ฝ่ายปฏิบัติการ | ผู้บริหารหลังรับรอง การทดสอบและตรวจรับโดยผู้ใช้งาน และ รายการตรวจก่อนเปิดระบบ |

### การแยกหน้าที่และความปลอดภัย

- ผู้สร้างไม่เป็น ผู้อนุมัติขั้นสุดท้าย ของ ใบเบิก ใบสั่งซื้อ รายการปรับปรุง ใบแจ้งหนี้ การจ่ายเงิน และ ระบบเงินเดือน ผู้จัดทำ สมุดรายวัน ไม่เป็น ผู้บันทึกบัญชี และผู้จัดทำแบบภาษีไม่เป็น ผู้อนุมัติขั้นสุดท้าย
- ใช้ ข้อมูลมอบหมายบทบาทผู้ใช้ ข้อมูลสิทธิ์ตามบทบาท และ ขอบเขตข้อมูลที่มีสิทธิ์ เป็นสิทธิ์หลัก ตรวจซ้ำที่ เครื่องแม่ข่าย และฐานข้อมูลก่อน อ่านหรือเปลี่ยนข้อมูล
- แยกสิทธิ์เงินเดือน บัญชีธนาคาร เอกสารภาษีและ ส่งออกข้อมูล มี ปกปิดข้อมูลบางส่วน การอนุมัติเปลี่ยนบัญชี และ บันทึกตรวจสอบย้อนหลัง การเข้าถึง
- เก็บ เอกสารจำกัดสิทธิ์ และ ข้อมูลลับระบบ แยกจาก ระบบควบคุมรุ่นซอร์สโค้ด ใช้ การเชื่อมต่อเข้ารหัส และ สภาพแวดล้อมระบบ แยก พร้อม ระยะเก็บรักษาและการระงับทำลายข้อมูลตามข้อผูกพันทางกฎหมาย ที่บริษัทอนุมัติ
บริษัทแต่งตั้งชื่อผู้รับผิดชอบจริงและผู้แทนตามบทบาทก่อนเริ่ม การปรับโครงสร้างหรือย้ายข้อมูล และ การทดสอบและตรวจรับโดยผู้ใช้งาน ส่วนลงนามท้ายเอกสารใช้บันทึกผู้มีอำนาจและเงื่อนไขที่อนุมัติ


## 10 แผนทดสอบและเกณฑ์ตรวจรับ

ผลรับรองต้องผูกกับ รหัสชุดโค้ดส่งมอบ สภาพแวดล้อมระบบ ชุดข้อมูล กฎเวอร์ชัน และผู้ตรวจรับ รายการที่ไม่ได้ทดสอบระบุ ยังไม่ได้ทดสอบ หรือ ติดเงื่อนไขที่ยังไม่ผ่าน ไม่แสดง ผ่าน แทน

| กรณี | หัวข้อ | เกณฑ์ตรวจรับ |
| --- | --- | --- |
| U01 | ภาษีมูลค่าเพิ่ม และสาขา | วันที่มีผลถูกต้อง ใบเก่าคง สำเนาข้อมูล ณ เวลาออกเอกสาร และสิทธิ์ภาษีซื้อแยกชัด |
| U02 | ซื้อสินค้า | ใบรับสินค้า คลัง บัญชีสินค้ารับแล้วแต่ยังไม่ได้รับใบแจ้งหนี้ เจ้าหนี้การค้า ภาษีซื้อ และจ่าย กระทบตรงโดยไม่ลงต้นทุนซ้ำ |
| U03 | การตรวจคุณภาพ และคืนผู้ขาย | รับบางส่วน ปฏิเสธ คืน และลดหนี้อ้าง ข้อมูลต้นทาง และจำนวนถูกต้อง |
| U04 | งานจ้าง | ตรวจรับตามผลงาน เงินประกันผลงานและภาษีหัก ณ ที่จ่าย และ เจ้าหนี้การค้า โดยไม่เพิ่มสต็อกบริการ |
| U05 | ค่าบริการลูกค้า | ราคาเหมาจ่าย จำนวนกำลังคน การทำงานล่วงเวลา วันหยุด รายการหัก อ้างสัญญาและหลักฐาน |
| U06 | ลูกค้าหักภาษี | ยอดเงินสดและ เครดิตภาษีถูกหัก ณ ที่จ่าย รวมปิด ลูกหนี้การค้า ได้ โดยไม่มีเงินสดสมมติ |
| U07 | จ่ายหักภาษี | ปิด เจ้าหนี้การค้า ด้วย ธนาคาร และ ภาษีหัก ณ ที่จ่ายค้างนำส่ง แล้วนำส่งภาษีครั้งเดียว |
| U08 | คลังและต้นทุน | ต้นทุนเฉลี่ยถ่วงน้ำหนัก โอน คืน การนับจำนวนรายการ และ ต้นทุนรวมจนสินค้าพร้อมใช้งาน ตรง ยอดคงเหลือในบัญชีรายการเคลื่อนไหว และ บัญชีแยกประเภท |
| U09 | แบบ ภาษีมูลค่าเพิ่ม | ทะเบียน แบบภาษี เครดิต และ บัญชีคุม กระทบตรง |
| U10 | ยื่นเพิ่มเติม | เก็บ ฉบับต้นทาง และส่วนต่าง ไม่รวม ข้อมูลต้นทาง หรือจ่ายซ้ำ |
| U11 | ส่งข้อมูลภายนอก | หมดเวลารอผล ยังไม่ทราบผลแน่ชัด ใช้ รหัสอ้างอิง เดิมและตรวจ ข้อความแจ้งผลกลับ ซ้ำ |
| U12 | ธนาคาร | ผลจริง บางส่วน ไม่สำเร็จ และ รายการเดินบัญชี กระทบได้ ไม่ปิด ชำระยืนยันแล้ว ก่อนยืนยัน |
| U13 | ปิดงวดและ รายการกลับบัญชี | กัน บันทึกบัญชี งวดปิดและตรวจยอดสุทธิ ต้นฉบับ รวม รายการกลับบัญชี ถูกต้อง |
| U14 | ระบบเงินเดือน | งวด ข้อมูลลงเวลา การทำงานล่วงเวลา ยอดสะสมตั้งแต่ต้นปี ภาษี ประกันสังคม และยอดธนาคารตรงกัน |
| U15 | สิทธิ์และ การแยกหน้าที่ | กันข้ามบริษัท ไซต์ ฟิลด์ ผู้อนุมัติตนเองและ วาระการเข้าสู่ระบบ ที่หมดสิทธิ์ |
| U16 | นำเข้า | แสดงตัวอย่าง ข้อมูลขัดแย้ง ค่าตรวจสอบความถูกต้อง และ ทำซ้ำเมื่อเกิดข้อขัดข้อง ไม่สร้างข้อมูลซ้ำ |
| U17 | คืนระบบ | คืน ฐานข้อมูล เอกสารและ กลไกทำงานอัตโนมัติในฐานข้อมูล แล้วตรวจยอดและแผนกลับได้จริง |
| U18 | รายงาน | ลูกหนี้การค้า เจ้าหนี้การค้า สินค้าคงคลัง บัญชีแยกประเภท ภาษี เงินสด และกำไรไซต์ ตรวจย้อนกลับ ถึง ข้อมูลต้นทาง |

เกณฑ์คุณภาพงานพัฒนาประกอบด้วยการตรวจแบบข้อมูล สร้างส่วนเชื่อมฐานข้อมูล ตรวจสถานะชุดปรับโครงสร้าง ตรวจชนิดข้อมูล ทดสอบหน่วยย่อยและการเชื่อมงาน ตรวจเส้นทาง สร้างชุดโปรแกรมจริง และทดสอบหน้าจออัตโนมัติ รวมถึงทดสอบกลไกประมวลผลและบริการภายนอกบนระบบทดสอบ พร้อมให้บริษัทรับรองยอด


## 11 แผนเปิดใช้งาน ความเสี่ยงและการส่งมอบ

### เปิดทุกโมดูลพร้อมกันหลังผ่าน การทดสอบและตรวจรับโดยผู้ใช้งาน

ก่อนวันเปิด ให้บริษัทอนุมัติ การซ้อมย้ายข้อมูลครั้งสุดท้าย รายงานยอด รายการเอกสารเปิดค้าง ผู้ใช้และสิทธิ์ คู่มือ และผู้รับผิดชอบ ดูแลช่วยเหลือผู้ใช้ จากนั้นประกาศช่วงหยุดแก้เว็บและ Excel เก็บ ข้อมูลส่วนต่างครั้งสุดท้าย ย้ายข้อมูล ตรวจยอดและ การทดสอบการทำงานหลักหลังติดตั้ง แล้วผู้มีอำนาจอนุมัติเปิดจริง

หากเงื่อนไข การทดสอบและตรวจรับโดยผู้ใช้งาน ข้อมูล ภาษี ผู้ให้บริการภายนอก หรือ กู้คืนข้อมูล ยังไม่ผ่าน ให้เลื่อน เปิดใช้งานจริง โดยพัฒนาต่อบน ระบบทดสอบก่อนใช้งานจริง ก่อนการส่งภายนอกจริงสามารถคืน รุ่นโปรแกรม ที่เข้ากันได้ แต่หลังเกิดการจ่ายหรือแบบที่ได้รับแล้ว ต้องใช้ การกระทบยอด และ การแก้ไขด้วยรายการใหม่ที่ตรวจสอบย้อนกลับได้ ไม่ กู้คืนข้อมูล ทับหลักฐานธุรกรรมภายนอก

| ความเสี่ยง | มาตรการและผู้รับผิดชอบ |
| --- | --- |
| ข้อมูลเว็บกับ Excel ขัดกัน | เจ้าของข้อมูลอนุมัติ ข้อมูลขัดแย้ง รายโมดูล พร้อม ค่าตรวจสอบความถูกต้อง การจับคู่ข้อมูล และ ยอดรวมควบคุม |
| ฐานเดิมไม่ตรง การปรับโครงสร้างหรือย้ายข้อมูล | ทีมเทคนิค และ ทีมดูแลระบบ สำรอง คืนบน สำเนาระบบ และตรวจผลของแต่ละ การปรับโครงสร้างหรือย้ายข้อมูล ก่อน ฐานอ้างอิงที่รับรอง |
| กฎเงินเดือน ภาษีหรือ การวางบิล ไม่ยืนยัน | ฝ่ายบุคคล บัญชีและ ฝ่ายปฏิบัติการ ลงนาม ตารางกฎที่อนุมัติ ก่อนคำนวณจริง |
| ผู้ให้บริการภายนอก หรือ ช่องทางเชื่อมต่อระบบ ไม่พร้อม | ใช้ช่องทางไฟล์หรือ ช่องทางที่ผู้ใช้ดำเนินการ ที่อนุมัติ และเปิด ช่องทางเชื่อมต่อระบบ เฉพาะ ความสามารถที่รองรับ ที่ทดสอบแล้ว |
| ข้อมูลลับหรือการอนุมัติผิด | ความปลอดภัย และ ฝ่ายการเงิน ใช้ ขอบเขตสิทธิ์ ปกปิดข้อมูลบางส่วน ผู้จัดทำและผู้ตรวจทานแยกกัน บัญชีธนาคารที่ตรวจยืนยันแล้ว และ บันทึกตรวจสอบย้อนหลัง |
| เปิดพร้อมกันมีผลกระทบกว้าง | ซ้อม ตัดเข้าสู่ระบบใหม่ ทั้งวงจร มี รายการตรวจเพื่อตัดสินใจเปิดหรือเลื่อนระบบ ผู้ตัดสินใจและ ดูแลช่วยเหลือผู้ใช้ ผู้รับผิดชอบ |

### สิ่งส่งมอบและการควบคุมการเปลี่ยนแปลง

ส่งมอบ ซอร์สโค้ด และ ชุดคำสั่งปรับโครงสร้างฐานข้อมูล ที่ ตรวจทาน แล้ว แบบข้อมูลและ ช่องทางเชื่อมต่อระบบ เอกสารกฎและ การจับคู่ข้อมูล ผลทดสอบ การทดสอบและตรวจรับโดยผู้ใช้งาน คู่มือผู้ใช้และผู้ดูแล วิธี การสำรองข้อมูล กู้คืนข้อมูล ติดตั้งระบบ ย้อนกลับรุ่นก่อน และทะเบียนผู้รับผิดชอบ ใช้ รายการปัญหา และ คำขอเปลี่ยนแปลง บันทึกผลต่อขอบเขตงาน ปริมาณงานและทรัพยากร งบ วันส่งมอบและการทดสอบ ก่อนอนุมัติเปลี่ยนแผน

หลังเปิดระบบให้มีผู้รับเรื่อง ช่องทางแจ้งปัญหา การจัดระดับความรุนแรง การติดตามคิวและยอดผิดปกติ รวมถึงการส่งต่อเจ้าของธุรกิจ รายละเอียดเวลาบริการและเงื่อนไขดูแลให้ระบุในข้อตกลงการให้บริการที่บริษัทอนุมัติ
